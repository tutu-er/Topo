# 第四轮协议与实现复核

本轮在看完主800日和补充1408日后提出，属于新的方法开发轮。固定使用原44个历史，每历史16条新日，共704条；随机流基数7000000，与前两批5000000、6000000分离。原候选、参数、历史评分、设备、费用和最终完整原生选模保持冻结。

原始development/history_holdout标记仅为来源分组保留。由于此前原留出历史的结果已用于本轮诊断，它们不再是本轮未接触的历史验证集；本轮独立的是新日随机路径，不是新的历史样本。

两种新方法只增加规划方向限制。对每个节点，用原64个训练点做过原点的P/Q回归，得到κ；约束24个决策小时内的调整量满足：

`sum_h,n (Δq_hn−κ_n Δp_hn)² ≤ scale² ×24×base_kw²×sum_n mean_train(q_n−κ_n p_n)²`。

右侧训练数据使用pu，乘功率基准平方后与左侧kW/kVAr调整量一致。直接把96个15分钟点的平方和除以4，与24小时平方和相同。这里是偏离历史关系的平方和，不是采购电能。二次项为CᵀC，增加的是凸二次约束，整套问题仍为QCQP；2倍幅度对应4倍平方和预算。

这个限制的量级来自历史观测，是控制外推幅度的设计选择。它限制调整量，不限制新日基线与训练分布的差异，也没有修正候选电压均值。因此它可以检验是否减少不可靠行动，而不会自动纠正“零动作已经充分”的概率误判。受限QCQP不可行只针对这个更小的规划域。

四种方法均获得同一份原始初值和两档径向缩放初值，生成时间计入每种方法预算。应在本轮相同新日中比较原方向保护与两种限制；跨轮差异还包含随机路径及初值池变化。新增初值可能与原点重合，保存数按初值记录计，不宣称全部互异。

实际执行继续使用原设备域。由于资源响应各不相同，交付后可能超出附加方向限制，单独记录在`delivered_trust.json`，不计作物理设备违规。核验同时检查未改变的物理约束和每个方法的规划约束。

小样本检查覆盖6条含非零行动的新日、24个报价、108次原生选择、594条初值资源记录、396条径向缩放记录和891条证据判定，数值复算无错误。独立以kW回归得到的κ与预算和实现一致，预算误差不超过7.1×10⁻¹⁵。

发现并保留一项收据缺陷：运行版本把字典传给仅支持数值数组的`contract_hash`，使`training_pq_sha256`含对象地址而无法跨进程复现。该字段只用于收据和配置元数据，约束、κ、二次矩阵、预算和求解均不读取它。原收据及快照保持原样；核验依原观测文件哈希与另存的labels/P/Q数值数组规范哈希核对来源，缺陷次数与数值结果分开报告。没有为这一元数据问题重跑AC或改变运行中的模型。

首次四日预检的8条哈希差异已保留；扩展核验过程中另纠正了审计脚本对旧`qcqp_feasible`字段的理解：该字段只表示证据约束，规划域资格另存。修正后的检查分别核对二者，并检查实际选用初值同时满足两者。完整核验将在704条新日完成后进行。

现已完成704条全量核验：数值错误0，1408条旧哈希收据缺陷单列。运行结束后，未来版本已把该字段修正为数值数组规范哈希并通过跨进程回归；原批次快照和收据未覆盖。完整结果见[第四轮核验](reports/iteration4_pq/VERIFY.md)。

规划信息边界也作了精确复核：旧`context`是执行共用容器，包含离线truth，并整体交给`quote`适配器；该适配器实际只读取case/score/train/val/means/voltage_sigma，数学求解器只接收这些对象。全部400份score递归扫描未发现离线真值或正确性字段，适配器新增的native_bank来自冻结拟合。旧`truth_not_passed_to_planner`在数学求解器入口成立，但若把外层适配器也称planner，表述过强。未来版本已增加六字段allowlist，排除truth、真实未来观测及响应；旧记录保持原样，数值结果无需重新仿真。
