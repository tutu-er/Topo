# 有限用户端的光伏、EV和热泵灵活性算例

已在现有 `paper15` 物理网络上配置独立资源算例 `paper15_customer_flexibility_v1`。原网络有22个母线、15个表计接入点；本例在其中6个接入点放置8项设备。设备位置事前按表计编号分散选择，不读取真实支路、辨识候选或后续调节效果。隐藏分叉节点保持零注入，原线路参数保持原版本。

已完成设备线性约束、原期望对数赔率增量接口、48个逐时调节范围问题和7个确定性参考日方案的AC核验。结果见 [results/SUMMARY.json](results/SUMMARY.json)。本阶段验收对象是资源配置及接口；辨识改善和信息约束下的最小采购费用留给后续正式测试。

## 线性响应和约束

一天从08:00到次日08:00，24个小时决策，每个决策保持到该小时的4个15分钟量测点。`u[h,r]` 为设备相对原计划增加的净用电功率，单位kW。增加光伏发电对应负的u，限发对应正的u。

每个设备采用线性关系：

\[
p_{h,r}=p^0_{h,r}+u_{h,r},\qquad
\underline p_{h,r}\le p_{h,r}\le\overline p_{h,r}.
\]

同一表计下的设备功率相加。光伏和EV的无功变化取0，热泵取固定功率因数0.95，因此其无功变化为 `tan(acos(.95))*u`。这里u是已成交的调节功率，交付对请求线性；本例不拟合用户的电价弹性。

光伏可用出力为直流容量乘以事前设定的日照曲线，再按交流逆变器容量截断。主例基线使用全部交流可用出力，因此可付费限发，恢复弃光的基线余量为0。接口允许另行指定有来源的既有限发基线；组件超过逆变器容量的部分仍受交流容量限制。未提供限发来源时，模型拒绝人为降低光伏基线。

EV仅在接入期间充电，功率为0—3.68 kW，每个充电窗口交付电池侧7.5 kWh。基线已满足该需求，调节必须保持：

\[
\sum_h 0.9u_{h,r}\Delta t=0.
\]

所有EV实际充电功率非负；提前、延后充电即可相对基线双向调节。

热设备用储热量偏差z表示温度变化，初始和终端偏差均为0：

\[
z_{h+1}=0.98z_h+3u_h\Delta t,\qquad
T_h=47.5+z_h/C,\quad 40\le T_h\le55.
\]

1000 L水的热容量C为1.16278 kWh/℃。每个水箱相对初始温度的储热余量为±8.72083 kWh（热量），对应电能尺度约±2.90694 kWh。模型将z消去，直接形成关于u的线性不等式和期末等式。

参考热泵基线在06:00—09:00取0.8 kW，17:00—22:00取1.0 kW，其余0.4 kW，每台13.8 kWh/日。模型按该基线生成保持47.5℃所对应的热需求，并检查热需求非负。这是可行参考日的构造；后续真实负荷测试应将热需求预测和实际执行分别处理。

## 费用

服务费用按实际调节的绝对电量计算，EV和热设备的补回用电也计费：

\[
C=\sum_{h,r}\big[c^+_{h,r}\max(u_{h,r},0)
 +c^-_{h,r}\max(-u_{h,r},0)\big]\Delta t.
\]

节点报价为明确标注的合成参数：

| 服务 | 节点基准报价（元/kWh） |
|---|---|
| 光伏限发 | 101:0.30，106:0.32，111:0.28 |
| 恢复已有限发出力 | 0.05；主例无此可用余量 |
| EV，增加／减少充电 | 104:0.10，108:0.12，114:0.08 |
| 热泵，增加／减少用电 | 106:0.15，114:0.12 |

07:00—10:00、17:00—22:00的服务报价乘1.25，00:00—07:00乘0.8，其余乘1。本例预留容量费为0，零调节服务费为0。转移负荷已按移出和补回两边付费，不再叠加另一笔完整的“每转移kWh”补偿。

另列不含网损的终端净电量估值：夜间0.3元/kWh、白天0.5元/kWh、17:00—22:00为0.8元/kWh，反送按同时间买价的90%。该项与服务费用分开，表示示例能源价值；实际DSO现金支出需要采用相应采购、零售和结算安排。

## QCQP接口

`CustomerCase.attach(model)` 将192个设备小时调节变量及192个绝对值计费辅助变量加入Gurobi模型，所有设备约束和计费约束均为线性，整数变量为0。

`CustomerCase.evidence(...)` 直接复用现有 `expected_logodds_admm_20261113/evidence.py` 的期望对数后验赔率增量，没有另设代理指标。`attach_evidence(model,u,evidence)` 将同一个96量测点增量精确写成小时变量上的二次约束，叠加后仍为QCQP。原冻结H、完整候选库、sigma²和后验评分不在本目录中重拟合。

```python
case = CustomerCase(labels=labels)  # 明确绑定观测的表计顺序
evidence = case.evidence(H, target, competitors, forecast, sigma2, base_kw, gamma)
u, fee = case.attach(model)
case.attach_evidence(model, u, evidence)
model.setObjective(fee)
model.Params.NonConvex = 2
```

`forecast` 是已包含设备基线的完整无DFS净P/Q预测，形状96×30，先P后Q，单位pu。`shift_pq_pu`只增加调节偏移；`device_baseline_pq_kw`用于从非柔性背景创建新算例，已有完整净功率中不再重复叠加设备基线。每次提取QCQP报价，应调用 `audit(u)` 和 `fee(u)` 重算实际约束及费用，另行保存原问题上下界、初值和实际改进。附加接口测试验证了固定可行点的费用及二次约束映射，尚未求解本例的信息采购QCQP。

## 已完成核验

9项测试通过，覆盖车辆电量、水箱递推与期末温度、光伏交流容量、同节点多设备的不同无功响应、节点顺序与单位换算、原完整H公式和新增QCQP接口的一致性。

48个LP分别求24小时增加／减少净用电的最大可行幅度，保留其他时段的补回安排；再用第二个LP，在保持该小时最大幅度至1e-8精度时最小化服务费。每一行对应一份不同的整日方案，逐小时最大值不能拼成一个整日调度。

| 时段 | 增加净用电上限 | 减少净用电上限 |
|---|---:|---:|
| 12:00—13:00 | 16.05 kW | 2.88 kW |
| 19:00—20:00 | 9.36 kW | 2.00 kW |
| 次日01:00—02:00 | 6.39 kW | 4.97 kW |

全天单个小时的最大增加／减少幅度分别为16.42/4.97 kW。两个方向不对称，来自光伏限发方向以及车辆和热设备的原计划。

原AC程序核验无DFS及上述三个小时两个方向的极值方案，共7份完整参考日计划，全部收敛，终端电压总体范围0.999270—1.014341 pu，均通过预设0.95—1.05 pu数值筛查。原始P/Q/V和调度轨迹保存在忽略的outputs中。网络文件缺少支路和变压器额定热限，本次核验覆盖设备约束和终端电压，未给出完整网络安全证书。

示例参考日的终端净电量为1994.04 kWh，不含网损的电量估值为1043.63元。中午最大增加方案的服务费4.37元，电量估值较基线增加6.55元；该方案仅针对一个小时最大幅度，费用不代表辨识任务的最小报价。
