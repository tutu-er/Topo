# 当前120秒预算怎样限制逐步加线

现有记录支持一个具体问题：单次MIQP上限等于整个方法上限，硬的一步会用尽W阶段，后续连接来不及尝试。
八项100和八项101均因 `forward_budget` 停止W；最后一步都有正训练收益且被接受，没有一项因 `no_gain` 停止。
这说明当前批次尚未走到“继续加线也没有训练收益”的状态。是否增加步骤能改善验证结果，仍需同输入检验。

## 三种历史设置

|设置|起点|总预算/秒|单次W原生上限/秒|预算含义|
|---|---|---:|---:|---|
|2026-10-31 ordinary|完整RNJ初始结构|300|30|单次上限占总计10%，已有完整结构可修|
|原large96主批|基础支持模型|14400|3600|输出预留600；E关闭时W约13800，E开启时W约6900|
|本批100|基础支持模型|120|120|输出预留12；W约108秒，实际由阶段截止时间限制|
|本批101|基础支持模型|120|120|W约54秒，余下结构时间给E|

原ordinary还有不同的MAE目标、输出和RNJ使用方式，不能把其较好结果直接归于30秒上限。
原large96的单步3600秒也可能很长，但其总时间与当前120秒不在同一数量级。
本批源码在每步设置 `min(阶段截止时间, 当前时间+per_mip_seconds)`，未给未来步骤单独保留时间。

## 本批实际证据

来源为 `outputs/identification_contribution_20261116_v1`：32/32方法已完成，0失败。
本节只读取协议和训练求解事件，没有使用真值、验证恢复率或第11天结果来筛例。

|方法|Soumalas四重复的W步数|Pengwah四重复的W步数|预试/原生总耗时（全部8项）|原生严格优于实际初值|
|---|---|---|---|---|
|100|4 / 4 / 3 / 3|1 / 1 / 1 / 1|8.877 / 853.398秒|1步|
|101|2 / 2 / 2 / 1|1 / 1 / 1 / 1|7.894 / 423.600秒|0步|

100共18步全部接受；101共11步全部接受。上表耗时分别是每种方法的两个网络、全部八项合计。
Soumalas若原生界闭合，可证明该次单连接子问题，仍不等于完整拓扑最优。

Pengwah的100最清楚地显示了时间分配问题：

|重复|当前训练目标|预试初值=原生=固定QP收尾|预试秒/新QP数|原生秒|状态/最终gap|
|---|---:|---:|---:|---:|---:|
|h00|3.679584567|2.120682695|1.492 / 27|106.162|9 / 42.08%|
|h01|3.637912430|2.129308287|1.510 / 28|106.206|9 / 53.24%|
|h02|3.597444309|2.111967303|1.289 / 25|106.397|9 / 34.88%|
|h03|3.618629268|2.109955552|1.323 / 28|106.411|9 / 52.86%|

四项都很快由连接池单支持QP预试找到收益；随后原生求解使用约106秒，没有改善该初值。
此处状态9表示达到时限，未证明基础点或初值最优。接受这一步后，剩余预算不足以启动第二次W。
原生gap仍大，但“预算主要用于第一步的界与搜索，未形成更多逐步连接”是记录中的事实。

101的Pengwah四项同样只有一次W，原生约51.73–52.74秒且均未改善初值；
E随后使用约53.70–53.90秒，单RNJ参考初值1.021被原样返回，最终gap约2.34%–2.48%。
E参考点带来的收益与原生搜索收益应分别报告。

## 最小后续核验

单独将100的原生单步上限改为10秒，总计120秒及其余设置不变，复用这八项完整输入与同一算法快照。
先看W能否走得更远、是否出现真正的 `no_gain`，再看验证选择；不预先认定步数更多等于恢复更好。
完整方案见 [PROTOCOL_CAP.md](PROTOCOL_CAP.md)。本节证据不支持直接改变生产默认时限。
