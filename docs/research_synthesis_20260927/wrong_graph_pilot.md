# 三份既有测量缓存上的受控错图机制诊断

日期：2026-09-27。**实际完成；仅为三个缓存案例的配对机制诊断。** 不属于 V3 的 3171 场景复验，不构成独立样本性能估计，也没有重新执行 RNJ、AC 仿真或校准。

最值得注意的结果是：跨支路交换两个终端标签后，真实终端 108 仍在候选中，但优化器选择 109，且直接迁移旧位置阈值得到的集合只有 109。这给出了“错误的图可能给出错误且很小的定位集合”的实际代码例子。它不证明新方法已经解决此问题。

运行前在脚本中固定两个合法改动，未根据结果挑选错误图：

这不是“只改变候选位置、其他所有变量完全固定”的单因素消融：改图后原入口还会重新估计 L1 线损、幅值输入和 R/X；删支撑也改变参数数目。它测试的是**同一个现有推断流程遇到受控错误字典时的整体反应**。若要进一步分离传播路径，需要后续增加冻结幅值与统一历史重拟合对照。

## 3. 实测结果

原增益阈值为 **23.5732683426008**，原位置 profile-gap cutoff 为 **2.75996554058679**。后面的“迁移阈值”和“迁移集合”只是直接沿用这两个数的压力诊断；错误树签名已经改变，旧校准不再适用。

| 字典 | 输入 | 最优区域/端点 | H0−H1 增益 | 超过原增益阈值 | 用原位置 cutoff 得到的事件集合 |
|---|---|---|---:|---|---|
| 原树 | null | 112 | 5.42621 | 否 | 正式不报告事件区域 |
| 删 `{108,109,110}` | null | 110 | 10.85887 | 否 | 未校准，不作事件区域主张 |
| 交换 101↔108 | null | 108 | 9.28337 | 否 | 未校准，不作事件区域主张 |
| 原树 | exp2 | `{101,102,103,104,105}` | 278.69444 | 是 | 原真实区域，单元素集合 |
| 删 `{108,109,110}` | exp2 | `{101,102,103,104,105}` | 280.95602 | 是 | 原真实区域，单元素集合 |
| 交换 101↔108 | exp2 | `{102,103,104,105,108}` | 182.68411 | 是 | 上述错误区域，原真实支撑已经不在候选域 |
| 原树 | exp3 | 108 | 346.89483 | 是 | `{108}` |
| 删 `{108,109,110}` | exp3 | 108 | 188.12236 | 是 | `{108,109}` |
| 交换 101↔108 | exp3 | 109 | 246.27698 | 是 | `{109}`，真实终端108仍在候选域 |

表内数值由本轮实际结果四舍五入；完整精度以 JSON 为准。区域用下游终端集合比较，没有跨树直接比较人工负数节点 ID。

正常输入仅有同一份 null 缓存：三个字典均未超过原增益阈值。**本例没有观察到旧阈值下的误报；不能据此声称错图会增加误报，也不能估计误报率。** null 的优化器候选从112变成110或108不构成窃电告警。

exp2 的交换失败包含候选遗漏；不能仅报告“选错了”而掩盖真实区域已被删出候选域。exp3 则更直接：真实终端仍在候选中，优化器偏向109，旧集合阈值也排除了108。二者分别对应候选域不足和域内错误排名。

原树上的告警采用已匹配的历史校准。本轮调用错误树时明确 `calibration=None`，所以结果中的 **valid_alarm 为 null**。`uncalibrated_old_threshold_alarm` 等字段是刻意命名的未校准阈值迁移诊断，不能改称95%可信窃电判断。

## 4. 这个小例子支持什么

支持：错误结构能通过现有模型改变位置排序和集合大小；原图下的校准不能不经验证迁移到错误图；删除相关层级和跨支路错误可能产生不同类型的定位退化。

不支持：该两种图错误代表自然辨识错误分布；任何新联合集合方法已改善覆盖；错误图下某种总体误报/覆盖保证；三相不平衡或现场窃电性能；错误完全来自某一个参数或幅值机制。

后续最有价值的配对消融是：

1. 冻结原幅值输入，仅改变位置字典，分离线损/幅值传播；
2. 原图与错图都用同一份独立正常历史重拟合固定支撑参数，再测试新事件；
3. 真实 clade 不在候选域时显式输出缺失，评价时不把它重新映射到错误树的祖先并计为正确；
4. 以独立错图校准或联合模型域校准重新建立区域阈值，然后才谈覆盖。

## 6. 为什么不直接宣称复验 V3

只读审计发现 V3 `rows/*.json` 保存 job、幅值、位置 profile 和误差摘要，没有保存所有 P/Q/y 与总表原始数组。因此不能仅凭已有 rows 对新图重新拟合。按冻结 job 调用 `simulate_theft_scenarios` 可重新生成量测而无需重跑 RNJ，但还应核对模拟器及其依赖版本、回放原结果，并把新图校准/测试预先分开。

当前三个缓存来自早先 CLI 案例，V3 目录保存了它们的推断示例；“与 V3 CLI 示例完全回放一致”和“重跑 V3 的3171场景”是两件事。本轮只做前者。
