# 单步线路替换消融

在同一棵估计树上检验两个问题。第一，允许撤销一条未锚定线路并同时换入一条新线路，能否改善辨识？第二，在两种方法都允许这样换线时，宽节点整数优化比贪心搜索多找回了哪些真实分组，付出了多少计算时间？

## 比较协议

- 输入为 21 张通过原始 SHA-256 校验的随机开发网。每网使用同一份八天端表有功、无功、电压量测和首端电压。起点取 [30 秒档记录](../four_feeders/random_time_limits.json)中第一次锚定 Tree MIQP 的输出，即首次节点搜索前的树。硬锚点从该次整树求解的实际约束恢复。
- 对照保留原有的单条加线。两个替换分支均可保留原树、使用同一原加线结果，或撤销一条未锚定的现有分组，在其原父接点选择至少两个、至多全部减一的直接子树重新组成一条线路。两步作为一个动作评分，避免因单独删除时评分变差而提前截断。每个方案均重拟合全树阻抗，选择惩罚评分 H 最低的可行树。
- 替换位置由当前估计树给定，两个替换分支逐一检查同一批位置。一个分支采用贪心搜索，另一个分支在至多 9 个子树时穷举，在更宽的接点上调用 Node MIQP。记录单步后的树、正确和错误分组数、F1、目标值、耗时及可用界。单节点界只覆盖该位置的替换。原始已验证方案始终作为可行备选。
- 首先复核 `dev_large_003_middle`、`dev_huge_003_middle`、`dev_huge_004_end`、`dev_huge_005_none`。此前查看过这些网的真值，它们用于诊断。另 17 网沿用同一规则。21 网均为开发网。盲搜阶段仅接收量测模型、估计树和锚点，真值仅用于输出后的计分。
- 单独核对 `dev_huge_004_end` 的指定收缩位置。位置来自先前的事后诊断；该位置的 10 个直接子树有 1,012 个合法并集。完整枚举与 Node MIQP 分别求解同一问题，候选按 H 排名，然后再对照物理真值。整网实验仍需从所有可撤销位置中自行选择。

从 `topology_study` 目录运行下列命令。整网计算使用已校验的随机开发库，可以从已发布结果读取锚点；固定接点穷举另需该网 30 秒档整树候选域的本地存档。求解命令将新结果写入本地 `outputs/`。整网入口通过 `--cases pilot` 和 `--cases other` 可分别运行两组馈线。`--stage verify` 从量测独立复核已归档的树与分组得失。

```powershell
python -B experiments/run.py line-exchange --cases all --workers 2
python -B experiments/run.py line-exchange --stage verify
python -B experiments/run.py exchange-reference
```

## 21 网的单步结果

| 馈线等权分组 F1 | 锚定起点 | 只允许加线 | 允许加线或贪心替换 | 允许加线或精确替换 |
| --- | ---: | ---: | ---: | ---: |
| 4 个诊断网 | 0.4986 | 0.5093 | 0.5144 | 0.5329 |
| 其余 17 个开发网 | 0.6382 | 0.6419 | 0.6340 | 0.6340 |
| 全部 21 网 | **0.6116** | **0.6167** | **0.6112** | **0.6148** |

表中每种方法对同一起点最多做一个动作。最后两列均在保留、原加线、各自找到的替换中选择 H 最低的可行树。相对只加线，开放精确替换使 5 网 F1 提高、14 网持平、2 网下降。降幅最大的是 `medium_003_middle`，由 0.375 降到 0.250。相对共同起点，只加线合计新命中 5 个真组、误增 4 个假组。开放精确替换新命中 7 个真组、误增 6 个假组，同时删除 3 个真组和 7 个假组。开放后 H 可以因换线而降低，选择规则会同时承担删去真线的代价。[逐网树、动作、线路得失及独立重拟合](results.json)

两种替换法各检查 187 个可收缩位置。精确分支在 168 个窄位置穷举，另在 9 网的 19 个宽位置调用 Node MIQP，实际宽度 10–17。21 网“在所有允许位置做至多一次替换”的评分间隙均闭合到规定容差。对比最后两列表中的最终树，20 网分组 F1 相同；`large_003_middle` 的贪心分支为 0.593、精确分支为 0.667，差异来自 **8 子树的穷举**。

宽节点求解有一个明确的局部差别。在 `huge_005_none` 的一个 10 子树位置，贪心保留原 11 表真组；Node MIQP 选出另一条 45 表真线 9→12，H 从 5248.676 降到 5156.985。两种替换法在考察该网其他位置后，都找到更低的 H 5099.416，并选择相同的整树。这一例展示求解器能跳出贪心的局部解，也区分了单个位置的改进与整网最后采用的动作。

每网从第一个位置扫到最后一个位置的实际计算时间中位数为贪心 2.29 秒、精确分支 6.80 秒。记录还以两种扫查中较短的累计计算时间为共同截止，只使用当时已完成的位置。这组时间比较只计替换搜索，原树取自存档，原加线另记耗时。完整扫查分别产生平均 F1 0.6091、0.6126，共同截止分别为 0.6091、0.6116。19 个宽位置均在首次 60 秒上限内达到容差。[各位置的界、实际用时与共同截止结果](results.json)

## 60 表固定接点的精确核验

在 `huge_004_end`，指定撤销覆盖表计 4–28 的旧组。它与 54 表真线 8→11 交叉。该例采用代码的零基表计编号。固定位置后，穷举及 MIQP 都只按量测评分排序。

| 该位置的可行树 | H |
| --- | ---: |
| 保留原树 | 7325.854 |
| 单独删去旧组 | 7463.920 |
| 换入 8→11，54 表，穷举第 3 名 | 7074.280 |
| 换入 6→8，56 表，穷举第 1 名 | **6975.922** |

两条真线均在原锚定候选池外。1,012 个候选中的第 2 名 H 为 7050.497。Node MIQP 用 2.06 秒取得与穷举一致的唯一最优分组，下界与可行值闭合；全枚举耗时 16.04 秒。早先的完整辨识流程已经通过窄节点加线找到 6→8，其最终树仍缺 8→11。[候选排名、单次耗时与独立重拟合](fixed_node.json)
