# v4指标、继承和费用的只读审查

本次审查核对当前代码、数学文件和开发协议，没有更改128份科学源码或冻结评价策略，也没有用评价结果选择新规则。

## 1. 主方法保证什么

每个参考拓扑 a 的完整AC分数为 m_a，平均目标为 Φ=K⁻¹∑_a m_a。FD、MC继承FC；MD先按相同Φ选择FD、MC中的最高者 p₀，并保留其完整操作。每次候选替换要求Φ严格提高，guarded另检查每个m_a相对当前锚点不下降超过数值容忍。

这与平均目标兼容：保留父解便可保证保存的Φ不下降，所选锚点也始终提供一个安全回退。主方法同时表达了保守偏好，实际搜索比无约束的max Φ更受限；它没有求解“物理域内最大Φ”的全局最优解。

保护适用于每次接受步骤。平方初值和MILP提案都可能被先后接受，因此最终参考分数相对最初直接父允许的下降为各次ε之和，单域最多两份。平均Φ每次仍严格提高，不因该容忍累计而下降。数学与协议已补充这一精确口径。

MD只对所选最高Φ直接父进行逐参考保护。例：FD的m=(2,6,6,6)，MC为(10,2,2,2)，其Φ分别为5、4；MD取(3,7,7,7)时相对所选FD各参考均提高，但第一个参考仍低于MC。即使预测完全正确，MD对未选MC的实际真参考分数也可能较低。这属于指标取舍，不是guard违反或移动建模错误。

## 2. 为什么可能拒绝Φ更高的平方计划

设当前m=(2,2,2,2)，Φ=2；某同域平方计划为(1,4,4,4)，Φ=3.25。aligned可以接受，guarded会因第一个参考下降而拒绝。故guarded的Φ低于同域square并不自动表明代码出错；应报告被保护参考、平均Φ代价，以及独立实际辨识结果。

如果只关注平均Φ，aligned是对应的消融；如果关注额外自由度是否在同一策略下导致规划倒退，检查同家族父子Φ继承。不要把“对父计划不退”写成“对所有其他策略都占优”。保护错误或预测不准的参考也可能阻止对真拓扑有用的动作，这是保守规则的代价。

## 3. 当前MILP与接受规则之间仍有搜索缺口

MILP优化校正后的平均距离代理，尚未包含每参考下限；代码只从最多两次解释交换的提案中，按代理下界选择一条，再作一次完整AC评分和guard检查。解释交换调整竞争参数解释，没有根据guard拒绝原因重新搜索。

以上例为例，若另有m=(2.5,2.5,2.5,2.5)的合法动作，它可以通过guard并提高Φ；但即使代理完全准确、MILP求到全局最优，也可能只提出Φ=3.25的牺牲方案，被拒绝后保留Φ=2，错过2.5。因而停滞可由提案机制造成，不能据此认定保护条件下没有更优解。这是实现范围和保守搜索的限制，不是接受规则失效。

后续新版本可研究把代理逐参考下限放入MILP，或在拒绝后进行一次针对受损参考的再规划。必须使用代理的有效下支持式，而不能用竞争解释提供的上界来证明分数下限；这些约束仍只保护冻结代理，完整AC接受检查应保留。父点QP有有限间隙时，下支持式可能不在父点达到完整AC分数，需要单列该数值差，不能为了保留父可行性而暗中改变正式保护条件。本轮冻结评价不调整这些规则。

## 4. 费用和缓存

代码层面的主要计费方向正确：

- square每域日志记录实际求得该域平方计划的增量耗时。aligned、guarded各自使用某平方初值时，都把该实测耗时加入本家族虚拟付款，未把缓存读取当免费初值。
- 每家族按FC、FD、MC、MD顺序推进，正常路径下各祖先平方计划已分别付款，后续域只付本域新增费用；父计划的完整AC评分通过同一objective_id缓存继承。没有重复按每个子域收费一遍祖先。
- aligned和guarded分别建立冷engine/cache，使用相同输入、选项和种子；引擎对同一动作使用固定初值与命名种子，没有依赖此前其他动作的热启动拟合，因此同目标缓存复用有依据。
- 家族报告actual_seconds与square_dependency_seconds，并给standalone_planning_seconds之和。实际重新执行平方优化没有发生，因此后者是“实测判别计算+实测依赖费用”的核算值，应与直接墙钟时间分列。
- 共同报告用的完整AC评分不参与square选计划，应作为报告/核查开销，而不是square优化费用；完整记录总耗时及全AC计数同时保留。

需精确说明的限制：

1. 300秒与75秒都是软预算。已知平方费用计入后可能不足，程序仍完成原子的完整AC初值评分；QP批次和完整AC提案也可跨过检查时刻。日志给出真实超额，不宜称为严格等时求解。
2. 75秒是当前域的增量配额，祖先成本计在家族总账；不能把它当作从零部署FD或MD的全部独立成本。square有300秒家族上限，没有相同75秒域配额；这属于预定预算分配差异，需与实际耗时、提案次数一起报告。
3. 平方虚拟费用使用四个域日志的增量耗时之和，未计入square_family构造公开曲线及权重等少量函数级开销。无明显的大项漏计；如需严格端到端费用，可在后续协议中把该公共准备费也按一次性依赖计入。
4. 极端失败路径下，若某祖先平方初值没有购买而后续使用了依赖它的预计算子域平方计划，仅按子域增量付款会漏掉祖先依赖。当前正常顺序避免这一情况；费用审计应核对所有实际使用的依赖闭包，保留异常路径，而不是仅凭name已付款标志作普遍保证。

开发4条历史已作逐账核对，证据保存于 `outputs/mobile_v4_development2/design_cost_review_v1.json`，包含4个原文件SHA与冻结策略身份：8个判别家族均购买了4域平方初值，付款精确等于4域增量时间和，依赖闭包没有漏项。未分摊的square函数级开销为0.000389–0.000448秒。standalone总账与actual+依赖费仅有分别取时产生的微秒差。

墙钟时间另有执行条件影响，不能直接解释为算法加速。开发n4的index2相同动作532372…，两家族得到完全相同评分、174次联合拟合nfev及174次联合AC评估，但aligned的完整profile为21.065秒，guarded为4.843秒。其他共同动作也有类似差异，两家族本条均计算7个profile、112次联合拟合。因而本轮耗时表应并列真实墙钟、profile/fit/nfev/AC调用数；资源和执行期差异未隔离时，不把这些墙钟比值当作guarded或缓存机制的固有提速。

## 5. 问题分类

未发现强制移动、正常路径丢失父计划，或跨家族免费借用完整AC策略缓存的错误。相对直接父只减单份ε的文字保证过强，已更正为逐步与累计容忍。拒绝Φ更高却损害参考的平方计划是已声明的保守选择。MILP没有逐参考下限、每域只验证一个提案，以及单域配额和依赖闭包的费用边界，是下一版本可以改进的内容；本轮保持冻结并据实报告。
